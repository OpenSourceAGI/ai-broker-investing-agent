This page takes a fresh checkout to a running dev server. It assumes nothing but
Node 20+ and a terminal.

## Prerequisites

| Requirement | Why |
| --- | --- |
| **Node.js ≥ 20** | Declared in the root `package.json` `engines` field. |
| **[Bun](https://bun.sh) 1.3+** | The repo's `packageManager`. `npm` and `pnpm` also work — every script is a plain npm script run through Turborepo. |
| **A [Cloudflare](https://dash.cloudflare.com) account** | Only needed to deploy or to talk to the production D1 database. Local development runs against a local Miniflare D1 and needs no account. |

## Install

```bash
git clone https://github.com/OpenSourceAGI/ai-broker-investing-agent.git
cd ai-broker-investing-agent
bun install
```

`bun install` installs every workspace in the monorepo — the web app under
`apps/`, and the shared packages under `packages/`.

## Create the local database

The app's only database is [Cloudflare D1](https://developers.cloudflare.com/d1/).
In development, Wrangler keeps a local SQLite copy of it under `.wrangler/`, so
you can apply the checked-in migrations without any credentials:

```bash
bun run db:migrate:local
```

<Callout type="info">
  Migrations are generated from `apps/ai-broker-web/lib/db/schema.ts` with
  Drizzle and live in `apps/ai-broker-web/migrations/`. See
  [Database](/docs/deployment/database) for the full workflow.
</Callout>

## Run the dev server

```bash
bun run dev
```

This starts `vinext dev` and opens [http://localhost:3000](http://localhost:3000). The server half runs
inside `workerd` — the same runtime as production — so the D1 and Email Workers
bindings declared in `wrangler.jsonc` are live in development too.

## Add API keys

Everything above works with no configuration. The AI agents, broker
integrations, and sign-in flows need credentials. Create
`apps/ai-broker-web/.env` and add the keys for the features you want:

```bash
# Model providers — at least one is needed for the debate agents
GROQ_API_KEY=
OPENAI_API_KEY=
GOOGLE_API_KEY=

# Auth
BETTER_AUTH_SECRET=          # openssl rand -base64 32
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
```

Every variable is optional and validated in `apps/ai-broker-web/env.ts`, so a
missing key degrades one feature rather than failing the build. The full list is
in [Configuration](/docs/getting-started/configuration).

## Common commands

Run these from the repository root; Turborepo fans each one out to the
workspaces that define it.

| Command | What it does |
| --- | --- |
| `bun run dev` | Dev server for every app. |
| `bun run build` | Builds the packages, then the web app. |
| `bun run test` | Vitest across all workspaces. |
| `bun run type-check` | `tsc --noEmit` across all workspaces. |
| `bun run preview` | Builds and serves the production Worker locally. |
| `bun run deploy` | Deploys to Cloudflare Workers. |
| `bun run docs:generate` | Recompiles the docs collections from `content/docs`. |
| `bun run docs:generate:api` | Regenerates the API reference from the OpenAPI spec. |

To scope a command to one workspace:

```bash
bunx turbo run build --filter=ai-broker-web
bunx turbo run test --filter=investing
```
